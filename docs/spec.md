# 星云（XY）首期 Spec

> 状态：2026-11-06 确认方案 B（基础业务闭环）；2026-11-09 根据已核对的教程正文修订创建体验与模块衔接。

## 目标与范围

让用户用自然语言创建静态网站，预览结果、连续修改，并将满意的版本部署分享或下载源码。

主流程：注册 / 登录 → 首页输入需求创建应用 → 自动进入工作台并开始首次生成 → 查看流式输出 → 生成成功后预览 → 对话修改 → 发布或下载。

- 首期：账号与登录、我的应用管理、单 HTML / HTML+CSS+JS 多文件生成、流式输出、预览、对话历史与记忆、多轮修改、静态部署分享、ZIP 源码下载。
- 首期生成的是静态前端应用；XY 平台自身具有 Java 后端。生成结果的动态服务端业务、数据库和用户系统不属于本期交付。
- 本期暂不实现 Vue 工程生成、工具调用、自动生成策略路由、元素选择编辑、工作流、封面、精选应用、管理后台和监控；这些对标能力保留在文末待办。

## 环境与实现起点

- 独立搭建：Java 21、Spring Boot 3、Maven Wrapper、MyBatis-Flex、MySQL、LangChain4j；Vue 3、TypeScript、Vite、Ant Design Vue、Pinia、Vue Router、Axios。初始化时核对兼容性并锁定具体版本。
- 使用模块化单体；按业务组织代码，参考通用规范的职责划分。通用技能的 Java 17 / Spring Boot 2.7 / MyBatis-Plus 模板与本项目不匹配，不直接复制为工程起点。
- 登录使用服务端 Session + Cookie；前端代理 `/api`。拟用前端端口 5173、后端端口 8101，初始化时确认可用；数据库使用用户已有实例，库名建议 `xy`，SQL 随对应功能放入 `backend/sql/`。
- 模型供应商、模型名称及接入参数由后端配置，接入前确认用户已有服务；密钥和密码不进入 Git。服务由用户在开发工具中启动。
- 发布使用用户授权的静态托管环境与独立站点来源；开发环境可验收本机链接，公网分享须在真实部署环境验证，不能用 localhost 链接代替公网交付。

## 数据

首期新增三张表；均包含 `id`、`createTime`、`updateTime`、`isDelete`，精确字段长度随模块 SQL 确定。下表列出首期目标结构；创建接口先落地应用基础字段，版本与部署字段随对应模块的 SQL 增加。

| 表 | 核心字段与类型 | 约束与用途 |
| --- | --- | --- |
| `user` | `userAccount` varchar、`userPassword` varchar、`userName` varchar、`userRole` varchar | 账号唯一；密码保存安全散列；角色为 `user` / `admin`，注册只能创建普通用户 |
| `app` | `userId` bigint、`appName` varchar、`initPrompt` text、`codeGenType` varchar、`generatedVersion` bigint 可空、`publishedVersion` bigint 可空、`deployKey` varchar 可空且唯一、`deployedAt` datetime 可空 | 记录创建者、初始需求、自动生成的名称、生成模式（默认 `multi_file`）、最近成功版本和已发布版本；版本引用成功生成的 AI 消息 ID |
| `chat_history` | `appId` bigint、`userId` bigint、`messageRole` varchar、`content` longtext、`status` varchar、`errorMessage` varchar 可空 | 角色为 `user` / `assistant`；状态为 `running` / `completed` / `failed` / `cancelled`；用户消息直接保存为 `completed`；失败原因只存可公开的文案 |

源码文件按用户、应用和生成版本隔离存放，不把完整项目文件写进数据库；一个 AI 消息 ID 同时标识一次生成，暂不新增任务表。

## 业务规则

- 账号：账号与密码必填，注册账号最多 128 个 Unicode 码点，与账号及初始昵称字段的存储上限一致；注册两次密码一致，账号不可重复；登录失败不泄露密码，响应不返回密码散列。
- 归属：平台应用、对话、预览、生成、发布和下载操作均由后端验证创建者身份；本期管理员身份不隐含访问他人私有应用的权限。
- 创建：只要求填写初始需求 `initPrompt`，不能为空且最多 16383 个 Unicode 码点，以保证可写入 `utf8mb4` 的 `TEXT` 字段；系统取其前 12 个码点作为应用名称，不要求用户另填名称。生成模式作为可选设置，省略或为 `null` 时由后端使用 `multi_file`，也可选择 `html`；其他取值返回 400，本期不在同一应用中切换模式。创建接口保存应用并返回字符串 ID，前端进入工作台后发起生成请求，用户无需重复输入需求。
- 重新进入：自动首次生成仅由创建成功后的进入触发。刷新或从列表打开已有应用时，先恢复历史与生成状态，不自动重发初始需求；已开始的任务展示真实状态，失败或取消由用户主动重试，尚未发起的初始需求可手动继续。
- 管理：我的应用支持按名称查询和分页，每页最多 20 个；更新信息只允许修改名称，名称不能为空。查看应用卡片进入工作台；已发布应用另提供“查看作品”入口，打开公开部署地址。应用 ID 在前端始终使用字符串。
- 生成：首次和后续请求都保存用户消息与 AI 回复，按应用加载上下文；后续请求结合最近成功源码，单 HTML 和多文件模式均生成完整的新版本。
- 历史与记忆：重新进入工作台可恢复对话，默认加载最近 10 条并支持向前加载更多；展示顺序为旧消息在上、新消息在下。历史展示和模型上下文分别处理，重新进入或服务重启后仍能基于已有网站继续修改，不同应用的记忆互不混用。
- 状态：AI 消息从 `running` 进入 `completed`、`failed` 或 `cancelled`；只有文件校验和保存成功后才标记完成。刷新页面后能查询真实状态，异常中断不得长期显示为正常生成中。
- 预览：工作台以对话和网站预览为核心；生成过程中展示流式文本，收到成功状态后才加载新版本预览，不能仅凭连接关闭判定成功。
- 失败：错误和取消必须明确展示；失败产物不能替换最近成功预览或已发布版本。用户主动重试才再次发起模型调用；断线不自动重新生成。
- 发布：只发布成功版本的快照，返回可访问地址；同一应用重新发布更新原分享地址，未发布的修改不影响线上版本。公开链接只展示网站，不提供私有对话或源码下载接口。
- 下载与删除：仅所有者可下载最近成功版本的完整源码 ZIP；无成功版本时禁止发布和下载。删除应用后私有数据不可访问，已发布链接停止提供该应用内容。
- 隔离：模型文件路径必须限制在所属应用目录；预览通过沙箱及来源隔离，不能获取平台凭证。源码包只包含生成文件，不包含平台配置、密钥或其他用户文件。

## 接口与页面

以下为拟定接口；统一前缀 `/api`，普通响应使用 `{ code, data, message }`。流式输出、文件下载和静态内容使用相应协议，不强行包装 JSON。

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| `GET /health` | 公开 | 验证后端与数据库连通性 |
| `POST /users/register`、`POST /users/login` | 公开 | 注册、登录 |
| `POST /users/logout`、`GET /users/me` | 登录 | 退出、当前用户 |
| `POST /apps` | 登录 | 接收初始需求及可选生成模式，自动命名并返回字符串应用 ID |
| `GET /apps/mine` | 登录 | 按名称查询自己的应用并分页，每页最多 20 个 |
| `GET /apps/{id}` | 创建者 | 返回字符串应用 ID、创建者 ID、名称、初始需求、模式与创建 / 更新时间；未登录 401、非创建者 403、不存在或已删除 404、非正数 ID 400 |
| `PATCH /apps/{id}`、`DELETE /apps/{id}` | 创建者 | 改名、删除 |
| `POST /apps/{id}/generations` | 创建者 | 提交需求并返回 SSE 事件流，包含生成 ID、增量输出和最终状态 |
| `POST /apps/{id}/generations/{generationId}/cancel` | 创建者 | 停止本次生成 |
| `GET /apps/{id}/messages` | 创建者 | 按游标查询历史消息和生成状态，默认最近 10 条，支持向前加载 |
| `GET /apps/{id}/preview` | 创建者 | 读取最近成功版本，直接返回带沙箱策略的 HTML；多文件模式合并 CSS/JS，缺失文件 404、无成功版本 409 |
| `POST /apps/{id}/deploy`、`GET /apps/{id}/source` | 创建者 | 发布快照、下载 ZIP |

公开分享地址由静态托管提供，不放在携带平台登录凭证的接口来源下。

| 页面 | 权限 | 主要操作 |
| --- | --- | --- |
| 注册页、登录页 | 公开 | 注册、登录、登录后回到目标页面 |
| 首页 | 公开浏览，创建与我的应用需登录 | 提示词输入与创建入口、可选生成模式；登录后展示我的应用，支持名称查询、分页、进入工作台及查看已发布作品；未登录提交时引导登录并保留需求 |
| 应用工作台 | 创建者 | 新建后自动首次生成，重新进入恢复历史与状态；桌面左侧对话、右侧预览，窄屏切换查看；支持停止生成、错误与重试、发布、下载，以及应用信息、改名和确认删除 |
| 已发布网站 | 持有公开地址者 | 直接浏览发布版本 |

## 模块顺序与验收

每步按一个可调用接口或一项可操作页面能力交付；模块开始时再拆步骤，代码检查和用户实际运行验收分别说明。

优先验收“首页输入需求 → 创建 → 自动生成 → 预览”，随后接入历史记忆和部署分享，再补齐列表管理。生成模块内部可先验证单 HTML，再接入多文件；首页默认多文件链路可用后，才算完成首次生成流程。消息保存、游标查询与状态恢复随生成模块接入，历史模块再补齐前端向前加载和模型记忆；只有保存记录、没有上下文时，不能宣称已支持持续修改。

| 顺序 | 模块与 XY 实现 | 验收条件 |
| --- | --- | --- |
| 0 | 工程骨架：独立初始化前后端与健康检查 | 后端检查通过；用户启动后能从前端代理访问数据库健康结果 |
| 1 | 账号基础：注册、登录、退出、当前用户信息与角色展示 | 注册后可登录；重复账号被拒绝；退出后不能访问受保护接口；管理员权限流程与用户管理仍为后续能力 |
| 2 | 应用入口：提示词创建、详情与工作台入口 | 只填需求即可创建；名称自动生成、模式默认多文件；可选单 HTML；创建后进入对应工作台，刷新后应用信息保留，另一账号不能读取详情；首次生成衔接在模块 3 验收 |
| 3 | AI 生成与预览：模型接入、两种原生模式、SSE、消息保存、状态查询、文件保存与隔离预览 | 创建后自动生成且无需重复输入；单 HTML 与多文件均可预览，样式和脚本正常加载；文件校验保存成功后才更新预览；失败、取消可辨认，刷新不重复生成，非法路径与无效产物被拒绝 |
| 4 | 历史与多轮修改：历史查询、模型上下文与成功版本衔接 | 重新进入恢复历史并可向前加载；已有应用不自动重发初始需求；修改基于已有网站生效，服务重启后仍可继续；不同应用的上下文互不混用 |
| 5 | 部署分享与源码下载：发布快照、公开链接、源码包 | 无成功版本时禁止发布和下载；未登录浏览器可打开发布版本；新修改在重新发布前不影响它，重新发布沿用原地址；ZIP 包含完整生成文件 |
| 6 | 我的应用管理：首页名称查询、分页、详情入口、改名和删除 | 只查询自己的应用，每页最多 20 个；从列表进入工作台恢复已有状态，已发布作品可直接打开；改名后刷新保留，另一账号不能修改或删除；删除后私有数据与分享链接均不可访问 |

### 模块 3：AI 生成与预览的实施步骤

| 步骤 | 改动范围 | 本步可验证结果 |
| --- | --- | --- |
| 1. 单 HTML 生成接口 | `generation/controller`、`generation/service`、模型配置、提示词、文件保存组件；`chat/model/entity`、`chat/mapper` 与对应 SQL | `POST /apps/{id}/generations` 校验创建者后调用模型并流式返回；保存用户消息与 AI 状态，校验并写入单 HTML 后才报告完成；失败不更新成功版本 |
| 2. 消息与状态查询 | `chat/controller`、`chat/service`、消息 VO 与查询 DTO；生成记录的重启恢复 | `GET /apps/{id}/messages` 返回最近消息和真实生成状态，可向前查询；进程中断遗留的运行中任务能被识别为失败 |
| 3. 停止生成 | 生成取消接口、运行中调用的停止与状态更新 | 创建者可取消运行中的生成；取消后不再保存为成功，不替换之前的成功版本 |
| 4. 成功版本预览 | `app` 模块预览接口、`manager/GeneratedFileManager` 版本文件读取与隔离策略 | 仅创建者能读取成功版本；无产物时明确报错，预览不能访问平台凭证 |
| 5. 多文件生成 | 多文件提示词、输出解析、路径校验及资源读取 | 同一生成接口支持默认 `multi_file`；HTML、CSS、JS 完整保存并可加载，非法路径与缺失产物被拒绝 |
| 6.1 工作台最近记录 | 消息类型与 API、工作台相邻的消息组件 | 进入后读取最近 10 条消息，显示完成、失败、停止与进行中状态；手动刷新仅查询状态，查询失败可重试 |
| 6.2 工作台生成操作 | 生成 API、SSE 解析、工作台生成交互 | 页面发起生成并显示流式内容、失败与停止操作；断线不自动重发请求 |
| 6.3 首次生成与预览衔接 | 首页创建跳转、工作台隔离预览、模块 E2E | 创建后自动首次生成；完成后预览，失败保留旧版本；刷新恢复状态且不重发请求，单 HTML 与多文件均可操作 |

第一步核对模型接入库的生成与流式协议并锁定依赖版本，真实网关兼容性由用户联调验证。模型接入信息只放服务端配置，自动测试用可控替身；生成模块完成后，再在模块 4 接入跨轮次模型上下文与基于已有源码的持续修改。

单 HTML 与多文件生成接口的当前契约：

- 请求：`POST /api/apps/{appId}/generations`，JSON 为 `{"prompt":"本次需求"}`。需求必填且最多 16383 个 Unicode 码点；首次调用传入应用的初始需求。
- 按应用创建时保存的 `codeGenType` 选择提示词与输出处理，支持 `html` 和默认的 `multi_file`；生成请求不重复传模式。
- 开始前返回普通 JSON 错误：未登录 401、非创建者 403、不存在 404、参数或不支持的模式 400、同一应用正在生成 409（业务码 50001）、模型未启用 503。
- 接受后返回 `text/event-stream`：`started` 带字符串 `generationId` 和 `status: running`；`delta` 额外带 `text`；最终为 `completed` / `status: completed`，或 `failed` / `status: failed`、`cancelled` / `status: cancelled` 与可读 `message`。流内失败或取消仍是 HTTP 200，连接关闭不代表成功。
- 生成 ID 是 AI 消息 ID。产物保存于 `用户ID/应用ID/生成ID/`，单 HTML 保存 `index.html`；多文件保存 `index.html`、`style.css`、`script.js`。所有文件校验和保存完成，且消息与应用成功版本在短事务内提交后，才发送完成事件。
- 多文件模型输出为 JSON 对象，键恰好是上述三个文件名，值均为非空源码字符串；HTML 必须完整，并通过相对地址引用 `style.css` 与 `script.js`（允许 `./` 前缀）。缺失、重复、额外文件、非法路径、错误引用、无效或截断 JSON 均失败，不更新成功版本。SSE 的 `delta` 与消息正文保留模型原始 JSON 文本。
- 当前多文件能力为固定三文件的原生静态网站；模块导入、任意目录和额外资源文件尚不支持，Vue 工程按后续阶段实现。
- 当前为单实例，同一应用同时只接受一次生成。超时或连接中断记录失败，取消已获得的模型流；句柄尚未到达时，后续回调会停止流。失败的部分输出保留为消息，但不会更新成功版本；重试必须由用户发起。
- 首次按本次需求生成，后续结合历史成功需求和最近成功源码生成完整新版本；上下文范围见模块 4。工作台支持创建后自动首次生成、手动提交需求、流式输出、停止与结束后读取记录。创建标记只在内存中消费一次，且历史为空才自动提交；详情或历史读取失败后由用户手动生成，刷新和重新进入不自动调用模型。

消息与状态查询的当前契约：

- `GET /api/apps/{appId}/messages` 仅创建者可访问；未登录 401，其他账号（包括管理员）403，不存在或已删除 404。查询限定当前应用和创建者，忽略已删除消息。
- 查询参数 `beforeId` 可省略；填写时必须为正数，只取小于该 ID 的消息。`pageSize` 默认 10，范围 1–20；非法参数返回 400。排序固定为 ID 倒序取最近记录，再将本页按旧到新返回，不提供任意排序。
- 普通响应的 `data` 为 `{ records, hasMore, nextCursor }`。`records` 包含字符串 `id`、`messageRole`、`content`、`status`、`errorMessage`、`createTime`、`updateTime`。有更早消息时，`nextCursor` 是本页最旧消息的字符串 ID；下次作为 `beforeId` 传入。末页与空列表均返回 `hasMore: false`、`nextCursor: null`。
- 每次进程启动后，首次通过权限校验的消息查询、停止请求或有效生成请求统一将遗留的 AI `running` 记录改为 `failed`，原因为“服务已重启，本次生成中断，请重试”。恢复成功后才允许新任务建立；失败则请求报错、下次重试恢复。只执行一次，不更改已结束消息、已保存内容或应用成功版本。该方式限定当前单实例部署。
- 运行期间，失败终态写入异常时在内存保留生成 ID、部分输出和失败原因；后续消息查询、生成或停止请求先重试补写。补写失败则请求报错并继续保留记录，成功后再返回消息；只更新仍为 `running` 的 AI 消息，已确认的终态或已删除记录不再重试。进程退出后由上述重启恢复处理，尚未落库的部分输出可能丢失。
- 本接口读取已保存内容与真实状态，不重新调用模型。当前运行中的增量文本只通过 SSE 提供；消息正文在完成、失败或取消时保存。重启可能丢失尚未落库的增量，但不会将中断生成报告为完成。
- 工作台默认读取最近 10 条，通过“加载更早消息”携带字符串游标向前查询，旧消息接到列表前面。失败保留已有消息和游标，允许重试；读完后显示已全部加载。刷新状态、生成结束或重新进入时回到最近 10 条，过期分页响应不能混入新列表；加载旧消息不触发生成或预览更新。

停止生成的当前契约：

- `POST /api/apps/{appId}/generations/{generationId}/cancel` 无需请求体。`generationId` 取 `started` 事件或消息查询中 `running` 的 AI 消息 ID；与应用 ID 分开传递。
- 仅应用创建者可操作；未登录 401、其他账号（含管理员）403、应用不存在 404、非正数 ID 400。必须匹配该应用当前运行中的生成；已结束、重复取消、不存在或不匹配的生成 ID 均返回 409 / 50001，提示刷新消息状态。
- 先将已有部分输出与 `cancelled` 状态保存，再请求停止模型流，释放该应用的生成占用并返回普通 JSON `data: true`；原 SSE 收到 `cancelled` 最终事件。保存失败返回错误，保留运行任务以便重试，不报告取消成功。
- 取消与完成回调串行决定最终状态：取消先成功时，迟到输出不能写文件或更新成功版本；完成先成功时，停止请求返回 409。旧生成的停止请求不能影响下一次生成；模型流句柄迟到时仍会请求停止它。

成功版本预览的当前契约：

- `GET /api/apps/{appId}/preview` 直接返回 `text/html;charset=UTF-8`；错误继续使用统一 JSON。仅创建者可访问，未登录 401、其他账号（含管理员）403、应用不存在 404、非正数 ID 400。
- 版本只取 `app.generatedVersion`，不接受客户端指定版本或文件路径；还需确认对应 AI 消息属于该应用和创建者，且状态为 `completed`。无成功版本或版本记录不匹配返回 409；文件不存在返回 404，文件不可读或含符号链接返回 500，不暴露本地路径。
- 当前从固定的 `用户ID/应用ID/生成ID/` 读取产物，下级目录与文件拒绝符号链接。单 HTML 直接返回；多文件将同版本的 CSS/JS 编码为 data URL 并替换 HTML 引用，磁盘上保留原始三文件。任何文件缺失均返回 404，不返回残缺页面。新生成失败、取消或尚未完成时，继续读取原有成功版本。
- 服务端以 CSP 响应头强制 `sandbox allow-scripts`，不授予同源权限；脚本和样式允许内联与 data URL，图片、字体及媒体限 data/blob 等策略允许的内联资源。禁止网络接口、HTTP(S) 外部脚本和样式、表单提交、子页面以及读取平台 Cookie、存储和父页面。生成内容自身的 meta 标签不能放宽响应头策略。
- 响应禁止缓存和发送 Referer。可在已登录的浏览器直接访问；工作台先检查预览响应，再用同源 `/api` 地址嵌入 iframe，设置 `sandbox="allow-scripts"` 与 `referrerpolicy="no-referrer"`，保留服务端 CSP。完成事件或历史中的成功版本变化时刷新预览；失败和停止保留已显示的成功页面。无成功版本显示空状态，读取失败显示重试入口；外部 CDN 和联网服务不在当前预览能力内。

### 模块 4：历史与多轮修改的实施步骤

| 步骤 | 改动范围 | 本步可验证结果 |
| --- | --- | --- |
| 1. 加载更早消息 | 消息查询类型与 API、工作台消息组件 | 复用已有游标接口向前加载，按旧到新展示，失败保留列表并可重试 |
| 2. 模型上下文 | 生成服务、持久化查询、成功源码读取与提示词、相关测试 | 按应用恢复历史与最近成功源码，两种模式均可持续修改，刷新和服务重启后仍能继续 |
| 3. 工作台修改体验 | 需求输入、重试交互、模块 E2E | 完成首次生成、后续修改、刷新后继续修改的页面流程；失败不覆盖已有成功版本 |

历史展示的分页状态仅保存在工作台组件中；模型记忆由后端从持久化数据恢复，二者独立处理。

模型上下文方案：在取得当前应用的生成占用后重新读取成功版本；按应用和创建者查询截至该版本的最近 20 条消息，提取其中完整成功轮次的用户需求（最多 10 轮），按旧到新排列。历史需求只作参考，以磁盘中的最近成功源码为修改基准，最后附本次需求；失败、取消、进行中的输出不发送给模型。本次需求只发送一次，没有成功版本时按本次需求首次生成。两种模式均返回完整新版本；成功记录或源码读取失败时明确结束为失败，保留旧版本，不能退回无上下文生成。
