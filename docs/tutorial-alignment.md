**插画服务的限制。** [unDraw 当前许可](https://undraw.co/license)要求集成、自动检索或抓取事先获得同意；本项目未提供此授权。未复用教程里的私有前端接口，没有把三幅本地插画记作已完成 unDraw 搜索。

**第 14 章的 Redis 驱动。** 本地正文中，用户服务、应用服务的依赖都排除了 Lettuce，使用 Jedis 连接池。XY 原来用了 Spring Session 和 Spring Cache，但驱动仍是 Lettuce；现在这两项和 Redis 对话记忆均使用 Spring Data Redis 的 Jedis 连接池，分布式限流仍使用独立的 Redisson。两个 Spring 实例的共享登录测试会检查实际连接工厂和池化状态。

**第 14 章「接口文档聚合」。** 教程在 Boot 3 下建议用导航跳转到各服务的文档。XY 在已有 Knife4j 入口内导航：[网关模式](../ops/gateway/README.md)列出应用和用户，两份 OpenAPI 仍由各自的 Spring 服务实时生成。用户分流后，登录只列在用户文档，级联删号只列在应用文档；无需旧版聚合 starter 或额外的文档服务。

**第 14 章「项目部署」。** 本地正文推荐用 Docker Compose 协调微服务及其依赖，没有给出一套可直接使用的清单。XY 的[独立编排](../ops/compose/README.md)包括应用和用户服务，以及真实 MySQL、Redis、Nacos、Higress。可叠加[截图配置](../ops/compose/covers.yaml)：应用发现独立的截图服务，发布快照由无网络的 Chromium 绘制。公网作品站和 gc 切流分别验收。

第 12 章「为生成的网站提供部署访问能力」使用 Nginx 提供静态作品。XY 在[本机作品站编排](../ops/compose/sites.yaml)中保留独立主机名，直接提供后端发布的快照。截图可单独开关，不是打开分享链接的前提。

**第 14 章的 Maven 版本管理。** 本地「父项目」和 Dubbo 配置导入了 Spring Cloud、Spring Cloud Alibaba、Dubbo 的 BOM。XY 此前只手写三个 Dubbo 依赖的版本，现在由[父 POM](../backend/pom.xml)统一导入官方清单：Spring Cloud 和 Alibaba 用适配本项目 Boot 3.5 的 2025.0 系列，Dubbo 保持 3.3.7。优先保留 Boot 的 Spring/Netty 组合、百炼 SDK 的 OkHttp 4.12，以及 Dubbo 使用的 Nacos 客户端 2.5.2。分别从变更前后的提交重新打包后，平台、用户和截图三个服务的 Apache HttpClient 均从 4.5.13 升至 4.5.14；只有平台还将 Commons Logging 从 1.2 升至 1.3.6。其余第三方 JAR 的内容不变。BOM 只管版本；注册发现仍由 Dubbo 完成，没有因此启用 Spring Cloud Gateway、Nacos Config 或其他服务。

**验证位置。** `SharedLoginSessionTest` 和 `GenerationMemoryRedisTest` 使用真实临时 Redis；`AiModelConfigurationTest` 走本地 HTTP 模型替身；`GenerationControllerTest` 覆盖输出、停止、工具和状态；`VueArtworkDeliveryTest` 对比两次源码交付的关系图；`ArtworkProvidersTest` 检查 Mermaid 请求、PNG 交付与 Logo 调用；`CosCoverStorageTest` 验证 SDK 请求及已有封面的兼容读取。外部 COS、真实付费模型、自托管 Kroki 和 gc 的线上配置不由这些测试证明。

前端从接口文档重复生成 5 个客户端文件，内容一致。另外把后端产出的 Mermaid 文本交给本地 Chromium 中的 Mermaid 11.12.2，实际绘出了 3 个节点、2 条连线及中文标签。
